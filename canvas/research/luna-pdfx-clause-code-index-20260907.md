# PDF/X clause and machine-code index

## Inventory boundary

This is a source-and-test inventory at exact HEAD
`f6bf1e78bfe80fac505c8b8c017d14962b0754c1` on
`codex/canvas-pdf-envelope-wiring-20260907`. It does not change source, tests,
the profile gate, or `PDFX_UNCOVERED`, and it does not make a standards or
conformance judgment.

The primary standard reference already retained by the name-encoding evidence
is [ISO 15930-7:2010](https://previewnorm.com/iso/ISO%2015930-7-2010%20PDF.pdf).
The clause labels below are used as an index only. “Checked” means that the
named local code runs and reports the listed machine codes; it does not mean
that the ISO clause is complete. “Rejected subset” means the Canvas writer
explicitly refuses a construct. “Absent” means no implementation or test was
found for that clause in the inspected paths.

Classification abbreviations:

- **E** — construct is emitted by the Canvas writer (`pdf.mjs`), then partially
  inspected by the checker;
- **C** — a bounded checker implementation exists;
- **R** — a Canvas-subset rejection exists;
- **U** — implementation or direct test coverage was not found;
- **P** — only partial/indirect coverage; not a clause-complete result.

## Writer-emitted versus rejected versus unchecked

### Observed writer-emitted constructs

`canvas/src/exporters/pdf.mjs` emits, subject to input capability selection:

- PDF 1.6 serialized output through `serializePdf16` for PDF/X-4;
- one output intent with the hash-pinned GRACoL2013 CRPC6 profile for PDF/X-4;
- Canvas source `DefaultRGB`/transparency group and page boxes;
- rectangle/ellipse/line/vector path content with the bounded operator set;
- ExtGState alpha (`ca`/`CA`) and bounded graphics-state use;
- full embedded Canvas font programs, Identity-H Type0/CIDFontType2 resources,
  and serialized glyph text;
- Canvas metadata/Info fields and document XMP for the PDF/X-4 candidate;
- rasterized image XObjects when the caller supplies the approved rasterizer.

These are emitter facts, not conformance results. The profile path still
rejects when subset verification is incomplete or when `conformant` remains
false (`pdf.mjs:66-80`).

### Explicitly rejected or outside the checked writer subset

The current code explicitly rejects or classifies as outside subset: object
streams/incremental/hybrid envelope forms; unsupported xref/reference forms;
unknown content operators and invalid operand shapes; unresolved or wrong-type
named resources; Form/PS XObjects; non-Identity font mappings; unsupported
image colors/filters/masks/decode parameters; alternate output profiles;
encryption/permissions; actions/presentations/optional content/halftones;
external references/streams; extra metadata streams; unsupported viewer box
values; and forbidden ExtGState transfer/graphics keys. Their machine codes
are listed by clause above.

### Unchecked or only partially checked

The current code does not establish complete PDF 1.6 grammar, complete
operator/resource coverage, all PDF/X architectural semantics, arbitrary
output-profile compatibility, non-Canvas fonts/Form content, incremental
metadata provenance, direct annotation/embedded-file/form semantics, or the
full original lexical spelling of parser-normalized semantic objects. Clauses
6.26 and 6.27 have no local implementation/reference or direct test in this
snapshot. These are inventory findings only; no clause is marked complete.
