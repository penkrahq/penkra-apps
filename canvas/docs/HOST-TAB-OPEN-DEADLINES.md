# Note for Penkra host: App-test tab-open deadlines

Canvas's startup split does not change host timeouts. The isolated `penkra app test` process wraps `openInstalled` in a **10,000 ms** phase timer (`apps/desktop/src/appTestHostPhases.ts:5,18-27`; call at `appTestHost.ts:99-107`). The normal host separately allows **15,000 ms** for preload bridge readiness (`apps/desktop/src/appRendererIpcBridge.ts:37,51-67`), and `appTabViewHost.ts:1802-1807` awaits that bridge and `loadURL` together. The preload signal (`appPreload.ts:172-176`) does not mean the App has painted. The 10-second phase can fail before the host's longer clock, even when the App would eventually load.

Please align these around one host-owned tab-readiness contract. The test's outer limit must cover that contract plus bounded setup/cleanup, rather than declare failure earlier than the production gate. Record preload-ready, document-load, and first-visible-frame separately so a slow App is not misdiagnosed as a preload failure. This is a host-side follow-up; no host source or timeout was changed as part of the Canvas implementation. The evidence and trace locations are in [TAB-OPEN-INVESTIGATION.md](TAB-OPEN-INVESTIGATION.md).
