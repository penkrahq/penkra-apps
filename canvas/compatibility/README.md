# `.pen` compatibility corpus

This directory is a format-research and preservation harness. It is not the
Canvas runtime or an internal editing-model commitment.

The first invariant is semantic preservation: parsing, inspecting, or changing
one supported property must not discard unknown document fields, unknown node
types, unknown node properties, or relative resource references. Format version
strings are recorded rather than restricted to a hard-coded allowlist because
Pencil documents in this workspace already use 2.15 while the public schema
documentation currently shows 2.14.

Run the corpus with:

```sh
node --test canvas/compatibility/pen-corpus.test.mjs
```

The checked-in oracle was generated by the real OpenPencil parser at the exact
commit recorded in `openpencil-oracle.json`. Re-run the differential whenever a
corpus file changes:

```sh
bun canvas/compatibility/openpencil-differential.mjs \
  --openpencil-root /path/to/open-pencil
```

The differential requires that exact OpenPencil commit and checks successful
import, stable source IDs, and deterministic graph shape. OpenPencil currently
reads `.pen` but does not export `.pen`, so it cannot serve as a lossless export
oracle. Penkra's preservation test separately proves that a supported edit does
not rewrite any unrelated or unknown JSON content.

  `tests/fixtures/pencil_simple.pen` under the same license and copyright.
- `unknown-content-2.15.pen` is a Penkra-authored forward-compatibility fixture.
- `unknown-properties-2.15.pen` is a Penkra-authored supported-node fixture with
  opaque fields at document and node levels.
- The test also reads the current first-party Pencil designs in this repository
  so the corpus covers real, evolving Penkra documents without duplicating them.

The real Pencil 1.2.3 open/save results are recorded in
[`pencil-1.2.3-observations.md`](./pencil-1.2.3-observations.md). They demonstrate
why Canvas cannot delegate lossless preservation to Pencil's serializer.
